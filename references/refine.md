# 图片调整迭代 — 决策表与指导（refine）

> 本文件是**按需加载**的参考信息，是"不满意后多次调整（多轮迭代，**不限次数**）"的**单一事实来源**。
> 总入口 `SKILL.md` 第 1 步路由与 `skills/image-refine/SKILL.md`（精炼版）都只引用/摘要本文件，
> 不另写一套。**聚焦图片**（文生图/图生图）；视频调整缺口另行处理。

## 定位

首次生成（`SKILL.md` 五步）解决"**从 0 到 1**"。本文件解决"**从 1 到 更好**"：
用户对已生成图片不满意，要求**多次调整（多轮迭代，不限次数）**时，需要三样东西——

1. **调整路由**：一句话判定这轮该走哪条调法；
2. **修改指导建议**：不满意症状 → 该拉哪个杠杆（一张决策表）；
3. **迭代状态**：这轮基于上一轮的哪张、改动哪个轴、哪些参数固化（可复现/可对比/可回滚）。

## 一、调整路由（先问两句，先定"重新生成 vs 基于旧图迭代"）

**第 1 句——"这张图该不该留作基准？"**（决定「重新生成」还是「基于旧图迭代」）

- **用户完全不喜欢 / 基本要推翻**这张（内容、方向、质量、风格都不满意）→
  **不要以它为基准图生图**——回到文生图**重新生成一张**（同词换 seed / 改词 / 换模型），把这轮视为"重来一轮"；
- **用户基本满意骨架，只是局部 / 方向要调** → 才以它为基准图生图迭代。

> **反模式提醒**：**别把"被否定的图"当 `--image` 基准**去做图生图——那会继承你讨厌的质感/构图/内容，
> 改不动根子。完全不喜欢就该**重新生成**，而非在原图上叠改动。

**第 2 句——"同方向换一个实例，还是换方向？"**（先定少动/大动）

- **少动**（构图/风格/主体都对，只是这版不理想，或只改一小点）→ seed 重 roll 或 低 denoise 迭代上一张；
- **大动**（风格/材质/场景要变、主体/构图本身错了、质量不行）→ 改提示词 / 换模型 / 高 denoise。

按"用户想改的程度"分层判定（**首行是"重新生成"分支**；由第 1 句决定"是否基于旧图"）：

| 用户想要 | 判据（用户话术） | 调法 |
|---|---|---|
| **完全不喜欢，要推翻重来** | "完全不行 / 受不了 / 整个重来 / 根本不是我要的" | **重新生成**（文生图；同词换 seed / 改词 / 换模型；**不基于旧图**） |
| 只是这版具体实例不理想 | "再来一张 / 换一下 / 同一风格再出一版" | **seed 重 roll**（文生图同词同参，仅换 seed） |
| 大方向对，只改细节/局部 | 指出具体元素（颜色/表情/某物/氛围） | **图生图迭代上一张**（低 denoise） |
| 整体风格/材质/场景要变 | "换写实 / 换季节 / 变傍晚 / 换材质" | **图生图 + 高 denoise** 或 **换模型 / 加风格 LoRA** |
| 构图/主体本身错了 | "主体不对 / 构图乱 / 少了X / 多了一个人" | **回提示词修词**（重跑或大改） |
| 质量不行 | "太糊 / 手坏了 / 不清晰 / 有畸变" | **提采样质量**（steps/cfg + 画质词 + 高清底模） |

> 判定要点：**先定「基准取舍」（重生成 or 基于旧图），再定「少动/大动」**。
> 同方向换实例 → 少动（种子/低 denoise）；换方向 → 大动（词/模型/高 denoise）。

## 二、"症状 → 杠杆"决策表（修改指导建议）

一次不满意往往需要**多杠杆组合**，但**每轮只动一个主导轴**（否则无法定位是哪个改动带来的）。

| # | 不满意点（症状） | 首选杠杆 | 关键操作 | 副作用 / 注意 |
|---|---|---|---|---|
| 1 | 构图/风格对，只是这版不理想 | **seed 重 roll** | 同词同参仅换 `--seed`，`--batch N` 可连出多张 | 每张都不同；想集中对比多张用 `--batch` |
| 2 | 细节/局部要改（脸/色/表情/某元素/氛围） | **图生图迭代上一张** | `image-to-image --image <上轮输出> --denoise 0.3–0.45`，提示词聚焦"改成什么" | denoise 低→小改但稳；高→易跑偏 |
| 3 | 风格/材质/场景大改 | **高 denoise 或换模型** | `--denoise 0.75–0.9`；或 `--checkpoint` 换风格底模 + 风格 LoRA | 换模型需 `validate`；大改可能连构图一起变 |
| 4 | 主体/构图本身错 | **改提示词重跑** | 改主体/构图词后文生图重跑，或图生图大改 | 词是根因，先修词再谈参数 |
| 5 | 质量不够（糊/噪/畸形/手坏） | **提采样质量** | `--steps 28–35`、微调 `--cfg`、加画质词、换高清底模 | cfg 过高易过饱和；steps 收益递减 |
| 6 | 想要多条候选再选 | **批量/扫描** | `--batch N`，或固定参数连出不同 seed | 耗显存/时间 |
| 7 | 只想改特定区域（局部重绘 / 可控生成） | ⚠️ **当前不支持** | 需 inpaint/ControlNet/IP-Adapter 专用工作流，现有模板缺失 | **边界**：先说明模板缺失，询问是否新增该工作流 |

### 杠杆作用与适用/不适用（补充说明）

| 杠杆 | 作用的维度 | 适用场景 | 不适用 / 注意 |
|---|---|---|---|
| `--seed` | 采样随机性 | 同方向换一个实例；多版本对比 | 不改变构图/风格/内容主体 |
| `--denoise`（图生图） | 与基准图的贴近程度 | 微调 0.3–0.45 / 风格迁移 0.5–0.7 / 大改 0.75–0.9 | 需 `--image` 基准；过高丢构图 |
| `--prompt/--negative` | 内容语义 | 改主体/细节/风格/构图；负面排错 | 词是根因，改词优先级最高 |
| `--checkpoint`（换模型） | 画风/质感/领域 | 换写实/二次元/风格模型 | 须 `validate`；跨栈换模板 |
| `--lora` (+strength) | 特定风格/质感 | 加风格、皮肤质感、特定镜头 | 须与底模同范式，否则报输入不匹配 |
| `--steps/--cfg` | 逼真度/遵循度 | 提升质量 | cfg 过高易过饱和；steps 收益递减 |
| `--width/--height` | 分辨率 | 放大/改画幅 | 改分辨率会重采样，可能改变构图 |
| `--workflow` | 模型栈/接入 | 跨栈（SD→Krea2 等） | **不跨栈自动换**，换栈必须换对应工作流 |

### 参数档位速查（指导性建议值）

> 常规模型（SD1.5/SDXL 类）的**建议档位**，承袭 `skills/image-to-image/SKILL.md`（denoise 阶梯）
> 与 `skills/text-to-image/SKILL.md`（steps）。依你模板 `_defaults` 微调；**每轮只动一个轴、固化 seed 与其它参数**。

| 想达到的效果 | 调整轴 | 建议值/区间 | 说明 |
|---|---|---|---|
| 微调 / 修瑕疵 / 提升质感 | `--denoise` | 0.3–0.45 | 最贴近原图，只动细节 |
| 风格迁移 / 换季节光照材质 | `--denoise` | 0.5–0.7 | 保构图、换氛围 |
| 大幅改动 / 只留大致构图 | `--denoise` | 0.75–0.9 | 易丢构图，须配准新提示词 |
| 提升细节/清晰度 | `--steps` | 28–35 | 细节不够时往上加 |
| 更贴提示词 / 更听话 | `--cfg` | 常规 6–8，上调 0.5–1 | 过高易过饱和/噪点 |
| 更自由 / 欠遵循 | `--cfg` | 下调 0.5–1 | 依需微调 |
| 换质感/画风 | `--checkpoint` / `--lora` | 见 `references/models.md` | 换模型须 `validate`；lora 须同范式 |
| 多版本对比 | `--seed` / `--batch` | `--batch N` 或连出不同 seed | 集中对比多张 |

## 三、迭代状态约定（可复现 / 可对比 / 可回滚）

每轮调整必须携带这份"上下文"，缺一不可——这是多轮调整区别于首次的关键：

```
【迭代上下文】第 N 轮   # N 可为任意轮（2、3、10...），不限次数
- 类型/工作流/模型：image-to-image / default_sd15_img2img / oneObsession_v23
- 基准输入图：第 N-1 轮输出（outputs/<类型>/<时间戳>_xxx.png）
- 基线参数：上轮 prompt / negative / seed / denoise / steps / cfg / 尺寸
- 本轮改动：<改了什么轴 + 为什么>
- 固化项：做 A/B 时固定 seed，除变化轴外其余参数不变
```

- **可复现**：同 seed + 同词 + 同参 ≈ 同结果；万一这版不如上一版，用固化的 seed/参数复现上一版回滚。
- **可对比**：每轮只动一个轴（如只变 denoise），才能判断"是不是这个改动带来的"。
- **可继续**：下一轮基准 = 这一轮输出，形成链。

### 基准图怎么取

- **文生图的 N 轮**：首轮是 `text-to-image`；进入"改细节/大改"时，基准 = 上一轮的**输出图**，走 `image-to-image`。
- **图生图的 N 轮**：基准 = 上一轮输出的**本地路径**（脚本已自动下载到 `outputs/<类型>/`），直接作为 `--image`。

> **不要取"被否定"的图当基准**：只有用户认可"骨架/方向"才拿它当 `--image`；
> 完全不喜欢 → 回到文生图**重生成**（不基于旧图）。

## 四、反馈收敛闭环

每轮交付后不要直接结束，给出明确下一步选项：

- 满意 → 保留；
- 再微调 → 进入第 N+1 轮（默认沿用"就近"杠杆，除非用户改了方向）；
- 大改方向 → 重新路由（换模型 / 换风格 / 换构图）；
- 回退 → 用固化 seed/参数复现上一版。

## 五、边界与诚实说明

- **局部重绘 / inpaint / ControlNet / IP-Adapter**：当前没有对应 worklfow 模板，本文件标注为"不支持，需新增工作流"。若高频需求，单独列为后续扩展。
- **seed 复现性**：同服务端 + 同模型下，同 seed + 同词 ≈ 同结果；但**跨模型/LoRA 不保证**。本文件目标定位为"相对自己上一轮做 A/B"，不承诺跨环境复现。
- **定位**：这是**决策指导**，最终"改哪个轴"仍需结合用户反馈由执行者判断；已把"可自动化/需确认"的边界说清，避免误导。
